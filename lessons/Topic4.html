02

What It Is & Why It Matters

Relational algebra

A formal language for manipulating relations. It describes how data can be retrieved and combined, using mathematical operations on relations (tables). Each operation produces a new relation as output.

Normalization helped us build clean tables. Relational algebra helps us use those tables to retrieve meaning.

That closure property — relation in, relation out — is what lets operators be chained. The output of one becomes the operand of the next, which is why a single expression can answer a complicated question.

Review of Key Concepts

Relational algebra operates on the vocabulary from Topic 2. Tap each term to see its definition and an example.

A table that represents a set of data about a single entity type or relationship. It has a name and a set of attributes (columns). Example: Student(student_id, name, email)

A row in a relation; represents one instance or record. Each tuple is unique within a relation. Example: (2023001, "Ria Borromeo", "rhborromeo@up.edu.ph")

A column in a relation; describes one property of the entity. Each attribute has a name and a defined domain, the set of valid values. Example: student_id, name, email

The set of allowed values for an attribute. Example: for grade, the domain could be {1.00, 1.25, 1.50, 1.75, 2.00, …, 3.00, 5.00}

The structure or definition of a relation — its name and attributes. Example: Student(student_id, name, email)

The actual data — the set of tuples in a relation at a given time. Example: the rows currently stored in Student.

Schema and instance are the pair worth keeping apart: an operator is defined against the schema, but it runs against the instance. That is why we can reason about a query before a single row exists.

04

The Operators

The operators divide into two families by how many relations they take as operands.

Type Operators Purpose
Unary Select (σ), Project (π), Rename (ρ) Act on one relation
Binary Union (∪), Intersection (∩), Difference (−), Product (×), Join (⋈) Combine relations

one operand

Unary

Select (σ), Project (π), Rename (ρ). These act on a single relation, cutting it down or relabelling it.

two operands

Binary

Union (∪), Intersection (∩), Difference (−), Product (×), Join (⋈). These combine two relations into one.

Whichever family an operator belongs to, the result is always a relation — never a single value, never a loose set of rows. That is what makes expressions composable.

05

SELECT — σ

Definition

The select operation is used to obtain a subset of the tuples from a relation — all the tuples satisfying a selection condition.

Suppose we need a list of male employees:

MALES ← σSex = "M" (EMPLOYEE)

Syntax

σcondition(RELATION)

A condition is built from:

<attributename> <comparisonoperator> <attributename>
<attributename> <comparisonoperator> <constant>
<condition> AND/OR <condition>
NOT <condition>

Examples: Sex = "M"; Age < 40; Sex = "M" AND Age < 40; Sex = "M" AND (Age < 40 OR Rich = True)

A RELATION is either a relation name or another relational algebra expression — which is how selections nest inside larger queries.

Other points about SELECT

  • It selects tuples satisfying a condition.
  • The resulting relation has the same schema as the operand.
  • The resulting relation’s population is less than or equal to that of the operand.

06

PROJECT — π

Definition

The project operation is used to obtain a subset of the attributes from a relation.

Suppose we need the first name and SSN of all employees:

NAMES ← πFname, SSN (EMPLOYEE)

Other points about PROJECT

πattributes(RELATION)

  • It selects attributes from a relation.
  • The resulting relation has a different schema than the operand.
  • Duplicates are eliminated — the result is a relation, and relations have no repeated tuples.
  • If the attributes on which we project form a super key, then the result and operand have the same population.

That last point is the useful test. Projecting onto a super key can never merge two rows, because a super key already distinguishes every tuple. Project onto anything less and rows may collapse.

07

Rows vs Columns

The output of a SELECT operation: row(s)
The output of a PROJECT operation: column(s)

The two unary workhorses cut a table along different axes, and almost every query uses them together: select the rows you care about, then project the columns you want to see.

σ · horizontal cut

SELECT keeps rows

Same schema, same or fewer tuples. Nothing is ever deduplicated, because nothing was merged.

π · vertical cut

PROJECT keeps columns

Different schema, same or fewer tuples. Duplicates that appear after dropping columns are removed.

Composed, they read inside out: πFname, SSN(σSex = "M"(EMPLOYEE)) is “the first names and SSNs of the male employees.”

08

RENAME — ρ

Definition

The rename operation lets us rename a relation, its attributes, or both.

For example, suppose we want to rename the EMPLOYEE relation WORKER and the Sex attribute Gender:

ρWORKER(FName, LName, Gender, SSN)(EMPLOYEE)

Renaming without the operator

Assignment to a new name does the job on its own:

NEWR ← R
R(FN, LN, SSN) ← πFname, Lname, SSN(EMPLOYEE)

Renaming with the operator

Three forms, depending on what you want to relabel.

Rename looks cosmetic, but it is what makes a relation joinable with itself, and what resolves the name clashes that cross product refuses to tolerate.

09

Set Operations

Operator Symbol Description
Union ∪ Combine results from two compatible relations
Intersection ∩ Return only common tuples
Difference − Return tuples in R but not in S

Type compatibility

These operators are binary and impose type compatibility between the two relations.

Type compatible · union compatible

Two relations R1(A1, …, An) and R2(B1, …, Bm) are type compatible when they have the same degree (m = n) and their attributes have the same domains.

∀i ∈ {1..n},   Dom(Ai) = Dom(Bi)

The operators

  • R ∪ S — set of tuples in R or S. Duplicate tuples are eliminated.
  • R ∩ S — set of tuples in both R and S.
  • R − S — set of tuples in R but not in S.

Note what type compatibility does not require: matching attribute names. It is degree and domains that must line up, position by position.

10

CROSS PRODUCT — ×

This binary operator creates all tuple combinations from two relations. Every row of R is paired with every row of S, so a relation of 2 tuples crossed with one of 3 gives 6.

It imposes that the two relations do not have attributes of the same name. To avoid this limitation we consider that all attribute names are prepended with the table name — here R’s A attribute is R.A; if S had an A attribute it would be S.A.

On its own, cross product is rarely what you want — most of those combinations are meaningless. It becomes useful the moment a selection is applied on top of it, which is exactly what a join is.

DIVISION — ÷

R(A1, …, An, …, Am) ÷ S(A1, …, An)

  • S’s attributes must be a subset of R’s.
  • The result relation has attributes An+1 to Am — the ones S does not cover.

R ÷ S = { ⟨an+1, …, am⟩  |  ∀⟨a1, …, an⟩ ∈ S, ⟨a1, …, an, …, am⟩ ∈ R }

In words

R ÷ S is the set of tuples that, when joined with every tuple in S, are in R.

It answers “for all” questions — which students took every course in a list, which suppliers deliver every product a project needs.

13

Additional Relational Operations

Generalized projection — π

This operation extends the projection operator to allow us to project on functions of the attributes. For example, if we have a database of objects with their prices excluding tax, and we want all objects with their price including tax at ten per cent:

πid, 1.1 × price(OBJECT)

The result column is computed, not stored — the underlying relation is untouched.

OUTER JOIN

Same as a JOIN, but it keeps tuples which do not have a match in the other table, padding with NULL.

OUTER UNION

Extends union to relations that are not type compatible but that have some attributes in common. It is equivalent to a FULL OUTER JOIN on the common attributes.

Both outer operations exist for the same reason: an inner join silently discards the rows that failed to match, and sometimes those rows are the answer — the employee with no department, the product nobody ordered.

—

Summary

  • Relational algebra is a formal language for manipulating relations. Every operation takes relations and produces a new relation, which is what makes expressions composable.
  • It is the theoretical foundation of SQL, defines how retrieval works under the hood, enables query optimization, and lets you reason about correctness.
  • Unary operators: Select (σ), Project (π), Rename (ρ). Binary operators: Union (∪), Intersection (∩), Difference (−), Product (×), Join (⋈).
  • σ returns rows: same schema, same or fewer tuples. π returns columns: different schema, duplicates eliminated, same population only when projecting onto a super key.
  • ρ renames a relation, its attributes, or both — and assignment (NEWR ← R) renames without the operator.
  • ∪, ∩, and − require type compatibility: same degree, and matching domains position by position.
  • × pairs every tuple of R with every tuple of S, and requires that no attribute name is shared.
  • A join is a cross product followed by a select. Theta join takes any condition, equijoin only equality, and natural join (*) is an equijoin on same-named attributes.
  • ÷ returns the tuples that, when joined with every tuple in S, are in R — the “for all” operator.
  • Outer joins keep unmatched tuples and pad with NULL; outer union extends union to relations that merely share some attributes.
